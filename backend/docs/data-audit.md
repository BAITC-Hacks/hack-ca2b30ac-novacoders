# Проверка локальных наборов, 23.09.2026

Срез отчётов: 22.09.2026. Проверены файлы в `backend/data/demo/iek` и
`backend/data/demo/electric_system`. Каноническое имя второй папки —
`system_electric`; загрузчик поддерживает оба имени, но отклоняет неоднозначный
выбор, если существуют обе папки. Книги при проверке не изменялись.

| Проверка | IEK | SystemElectric |
|---|---:|---:|
| Уникальные товары | 3185 | 4 |
| Детальные операции | 171603 | 825 |
| Отрицательные операции, сохранённые как возвраты/корректировки | 115 | 0 |
| Операции с неизвестным количеством, переданные как null | 18 | 0 |
| Месячные записи продаж | 81279 | 132 |

| Товары без известного полного количества в пути | 3185 | 0 |
| Размер JSON для AI, байт | 30529730 | 122972 |

SystemElectric содержит демонстрационные товары с артикулами `DEMO-001` —
`DEMO-004`, созданные генератором проекта. Это проверка технической цепочки;
для закупок нужны исходные отчёты SystemElectric. Существующие файлы автоматически
не заменяются и не дополняются сгенерированными данными.

В IEK найдено 8 повторных строк в MOQ/поставках, 15 некорректных числовых ячеек
MOQ и 18 строк без кода 1С. Повторные MOQ/поставки требуют проверки, строки без
кода не сопоставляются товарам. Повторные месячные строки суммируются по точному
`code1C` и месяцу; неизвестная часть суммы оставляет результат неизвестным.
Детальные операции не объединяются. Ведущие нули и `_` в кодах сохраняются.

В IEK по всей истории обнаружены 7275 расхождений между месячными и детальными
продажами и 318 случаев недостаточных данных для сверки. Это количества пар
«товар–месяц», а не уникальных товаров. В стандартном окне сентябрь 2025 —
август 2026 находится 3870 замечаний обоих типов. Старые замечания и неполный
сентябрь сохраняются в диагностике импорта, но не блокируют расчёт выбранных
12 полных месяцев. При включении сентября проверяются и его данные.

Свободный остаток IEK не выводится из исторических начальных остатков. Пустые
ячейки отдельных поставок означают неизвестное количество: частичная сумма
известных партий не выдаётся за полный товар в пути. Поэтому рекомендации IEK
требуют ручной проверки текущих остатков и поставок даже при успешном ответе AI.

Отрицательные продажи, нули и пропуски проверены отдельно. Некорректная
себестоимость, включая отрицательную, остаётся неизвестной. Отсутствующие месяцы
не считаются нулевым спросом. Количество заказа и прогноз не пересчитываются
во frontend; backend проверяет данные и контракт результата AI.

Воспроизведение проверки из `backend/`, без AI Service:

```bash
SUPPLYLENS_DATA_DIR="$PWD/data/demo" go test ./internal/recommendation -run TestLocalDatasetsContract -v
```

Настоящий AI Service на `127.0.0.1:8001` во время проверки не был запущен.
Для проверки транспорта используется отдельный тестовый HTTP endpoint;
качество прогнозных формул внешнего AI Service этим тестом не оценивается.
