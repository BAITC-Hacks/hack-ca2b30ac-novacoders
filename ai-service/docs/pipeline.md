# Этап 5: подключение pipeline

Существующие routes, схемы и алгоритм сохранены. Из lifespan передаются прежний AnalysisService и новый ExplanationService, использующие один ProviderClients. Контекст анализа — одна серия, ограниченные строки и обезличенные клиенты. Проверка evidence/типов/действий выполняется существующим AnalysisService. Применение корректировок остаётся за существующими бизнес-правилами алгоритма: модель не может подтвердить разовый заказ.

Объяснение получает только готовые расчётные компоненты, сформированные кодом причины, предупреждения и отдельно помеченные допущения. История продаж, ID клиентов, произвольный businessReason и ответ первого AI-вызова не передаются. Ответ — до трёх коротких качественных русских предложений со ссылками на допустимые причины. Невалидные ссылки, цифры, формулы, лишние поля и некорректная структура отклоняются в пользу template. Полная семантическая истинность свободного текста этим не доказывается; число заказа и обязательные предупреждения защищены конструкцией pipeline и не берутся из этого текста.

Использован прежний Responses/Pydantic адаптер согласно [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Модели и SDK-параметры не менялись; новые зависимости, tools, агенты и собственные повторы не добавлены. Вызовы последовательны, ограничены существующим timeout и оставшимся бюджетом запроса. Перед завершением оставляется резерв для формирования fallback. CPU-обработка и медленное чтение тела по-прежнему могут привести к общему HTTP 504; это не гарантия обработки произвольно большой партии в live.

Источники передаются существующими полями и предупреждением RESULT_SOURCES. OpenAI добавляет текст в explanation.details, Python сохраняет short и арифметику. Ошибка анализа — FAILED и needs_review; ошибка объяснения — template. Live без ключа — 503 AI_NOT_CONFIGURED. Макет синтетического ответа обновлён теми же Pydantic-моделями.

Проверено offline: полный HTTP pipeline с настоящим SDK-парсером и подменённым HTTP-транспортом; успех и отказ объяснения дают одинаковые 90; проверены сбой анализа, неизвестная строка, недопустимое объяснение, подтверждённая корректировка, таймауты, отсутствие ключа, лимиты объяснений, последовательная партия из двух товаров с изолированными контекстами и общим клиентом. Обычные тесты запрещают сеть. Реальных AI-вызовов не было.

Ручной smoke: `.venv313/bin/python scripts/smoke_pipeline.py` (offline, количество 90). Live-вариант `--live` документирован в README и не запускался. Блокер подтверждения реальной интеграции — отдельно разрешённая проверка доступа к настроенным моделям и фактической задержки API. Ключи и .env не читались/не изменялись.
