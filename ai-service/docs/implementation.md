# Результат этапа: самостоятельный mock-сервис

Исторический отчёт этапа 2. На этапе 3 архитектура переведена на единственный внешний провайдер OpenAI; актуальное состояние — в `openai-analysis.md`. Описание ниже фиксирует состояние на момент завершения этапа 2.

Дата: 2026-09-23. Все проектные изменения выполнены только в `ai-service/`. Исходный `alibekAI.md`, backend, frontend, корневые настройки и lock-файлы не изменялись. Commit/push/reset/clean/stash не выполнялись.

## Реализовано

- FastAPI application factory, `GET /health`, `POST /v1/recommendations`.
- Pydantic-модели запроса/ответа, сохранение v1 camelCase и поддержка snake_case; исходный пример запроса из `alibekAI.md` отдельно прошёл валидацию.
- Поддержка измерений SKU/склад/поставщик, стабильных ID строк, дат продаж/остатков/поставок, необязательных доступности/stockout/обезличенного клиента, сезонности и прироста.
- Минимум заказа и кратность представлены разными полями; неоднозначное старое `moq` сохранено как legacy-кратность. Подробнее в `../contracts/README.md`.
- Отдельные модули routes, schemas, settings, providers, algorithm, pipeline и tests.
- Согласованный mock: прогноз 60, потребность 49, округлённый заказ 50; отдельный результат на каждый входной составной ключ. Неизвестная стоимость — null. Все позиции `REVIEW`, `source=mock`, `is_demo=true`; провайдеры `SKIPPED`. История и настройки не используются как данные реального прогноза.
- Bearer-авторизация; без токена только явно локальный mock с loopback peer. CORS не добавлен.
- Настраиваемые таймауты, лимит байт с подсчётом чанков, лимит числа товаров; адаптеры SDK имеют общий семафор на экземпляр и запрещены вне разрешённого live-режима. В mock SDK-клиенты не создаются.
- `.env.example` с пустыми секретами и локальный `.gitignore`; `.env` не читался и не перезаписывался. `git check-ignore` подтвердил игнорирование `.env`; `git ls-files` не показал отслеживаемых `.env`-файлов. `.env.example` не игнорируется.
- Примеры JSON проходят модели, используемые HTTP API; response example соответствует mock-pipeline.

## Проверки

Рабочее окружение: `.venv313`, Python 3.13.0. Установлены FastAPI 0.141.1, Pydantic 2.13.5, pydantic-settings 2.15.0, openai 2.54.0, Uvicorn 0.53.0, pytest 9.1.1, httpx 0.28.1. Зависимости установлены в локальное окружение с разрешением на доступ к реестру пакетов. Рабочие тесты не требуют интернета и ключей.

- `.venv313/bin/python -m pytest -q`: 47 тестов прошли. Покрыты модели и примеры, HTTP, mock без SDK/сети, авторизация, потоковый размер, лимиты, таймауты, раздельные измерения, отсутствие мутации, конфигурация и адаптеры с явной тестовой подменой.
- `.venv313/bin/python -m compileall -q app tests`: успешно.
- `.venv313/bin/python -m pip --disable-pip-version-check --no-cache-dir check`: `No broken requirements found`.
- Реальный локальный запуск Uvicorn на `127.0.0.1:18001`: GET health и POST recommendations вернули 200; проверены source=mock, is_demo=true, сумма 50. Для локальных сокетов потребовалось разрешение песочницы. Временный сервер остановлен после проверки.
- `git diff --check -- ai-service` и отдельная проверка пробелов новых исходников/документов/примеров прошли. Git status содержит только файлы внутри `ai-service/`.

Остаётся одно предупреждение зависимости: Starlette предупреждает об устаревании httpx-адаптера TestClient и предлагает httpx2. Это предупреждение не подавлено, все тесты проходят. Отдельный lint/typecheck в проекте пока не настроен.

## Ограничения

Реальный алгоритм, анализ/проверка/применение аномалий и live/fallback-pipeline не реализованы на этом этапе. Адаптеры подготовлены, но не подключены к endpoint; `AI_MODE=live` возвращает 503 `LIVE_PIPELINE_NOT_IMPLEMENTED`, а не демонстрацию под видом модели. Health не проверяет доступность внешних моделей. Платные API не вызывались.

Расширения v1.1 пока являются локальной реализацией требований пользователя и требуют согласования с Go перед live-интеграцией. Нет хранения запусков, идемпотентного кеша, обработки Excel, экспорта или отправки заказов. Лимит конкурентных вызовов действует на экземпляр в процессе; будущий pipeline должен использовать один общий экземпляр. CPU-интенсивный алгоритм в будущем потребует отдельного способа ограничения времени исполнения.

Python 3.14 из Homebrew не смог завершить создание `.venv` из-за ошибки `pyexpat`/системной библиотеки. Системная установка не менялась; использован уже установленный Python 3.13. Незавершённое `.venv/` игнорируется и не используется. Команды запуска и запроса приведены в `../README.md`.
