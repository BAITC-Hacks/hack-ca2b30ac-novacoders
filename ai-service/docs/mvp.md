# Этап 4: Python MVP

POST /v1/recommendations рассчитывает входные данные, не возвращает константу. Контрольный пример: закрытые июнь/июль/август 150/155/155 единиц дают 5 единиц в день. Покрытие 20 + 10 дней → прогноз 150, запас 4 дня → 20, остаток 50, своевременная поставка 30 → заказ 90. Поставка 70 → заказ 50.

## Правила

- История ограничена historyMonths; используются только завершённые календарные месяцы до asOfDate. excludePartialMonth=false в этом baseline не включает неполный месяц. Пропущенные месяцы и неизвестные количества не считаются нулями. Неизвестные месяцы исключаются с предупреждением.
- Месячные количества делятся на фактическое число календарных дней. Средняя интенсивность взвешена по дням. Простой тренд при ≥3 месяцах — отношение последних floor(n/2) интенсивностей к первым, ограниченное 0.75–1.25; при короткой истории тренд 1 с предупреждением. Это baseline, качество не подтверждено backtest.
- Переданные сезонные коэффициенты сначала убираются из истории и один раз применяются к будущим дням. Для отсутствующих коэффициентов используется 1 с предупреждением; оценка сезонности не реализована. Нулевой исторический коэффициент требует проверки. Глобальная сезонность не различает категории/товары.
- additionalGrowthRate — дополнительный к тренду множитель 1 + rate, применяемый один раз. При отсутствии дополнительный прирост не закладывается.
- Покрытие = leadTimeDays + reviewPeriodDays; поля продукта имеют приоритет. Если не переданы, сохранены defaults settings: lead 30, review 30, safetyStockDays 14. forecastHorizonMonths сохранён в контракте, но не добавляет второй горизонт. Страховой запас — спрос за safetyStockDays после покрытия.
- Подтверждённый разовый заказ исключается только с businessReason и сверкой детализации с итогом. Без подтверждения предложения mock остаются needs_review. Для месячной метки исключается весь подтверждённый месячный объём. Исходные продажи сохраняются; аналитическая оценка отдельная.
- Подтверждённые дни stockout оцениваются по среднему дневному спросу других месяцев без заявленного stockout, с учётом сезонности. Непересекающиеся интервалы обязательны. При отсутствии сравнимых месяцев — null и missingFields. Нулевой остаток на конец месяца не запускает компенсацию. Сопоставимость месяцев — упрощённое предположение baseline.
- Нужен свободный остаток на asOfDate; он может быть рассчитан как totalStock − reservedStock, только когда оба значения известны. Устаревший/недатированный остаток требует проверки.
- Поставки учитываются строго после asOfDate и до asOfDate + leadTimeDays включительно. Неизвестная дата, просроченная или более поздняя поставка не вычитается и вызывает предупреждение. Это консервативное правило MVP, не посуточная симуляция запасов. FREE_ONLY не вычитает поставки.
- incomingShipments=[] явно означает отсутствие детализированных поставок. Если массив отсутствует, inTransit=0 подтверждает отсутствие, положительный агрегат без дат не вычитается с предупреждением; неизвестный агрегат требует missingFields.
- Положительная потребность поднимается до minimumOrderQuantity и округляется вверх к общему шагу orderMultiple и quantityStep. 93/20/1 → 93; 93/20/20 → 100; потребность 0 → 0. Старый moq означает кратность, не минимум.
- При критических пробелах quantity=null, action=REVIEW, processingStatus=needs_review, missingFields. При предупреждениях возможна предварительная числовая рекомендация с REVIEW. Неизвестная цена не мешает количеству: стоимость null.

## Источники и ограничения

Python baseline и шаблон объяснения работают без ключей и сети. Mock analysis подключён явно и никогда не выдаётся за OpenAI. Внешний OpenAI-клиент предыдущего этапа сохранён, но HTTP pipeline не вызывает его даже при AI_MODE=live. is_demo запроса маркирует синтетический вход; mock analysis имеет отдельную demo-метку. Исходные исторические отчёты сохранены с дополнением.

Нет БД, очередей, Excel, новых зависимостей и отправки заказов. Лимиты HTTP и авторизация сохранены. Синхронный расчёт внутри async endpoint не гарантирует жёсткое прерывание по deadline при CPU-перегрузке. Go нужно поддержать новые optional поля и nullable числовые результаты; имена маршрутов/старых полей не изменены.

Прежние тесты анализа, SDK, авторизации и HTTP-лимитов сохранены. Команды запуска и curl — в README.md.
