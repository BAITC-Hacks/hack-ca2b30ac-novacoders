# Правила работы в ai-service

## Область изменений

- Изменять только `ai-service/`.
- Не менять backend, frontend, корневые настройки и lock-файлы.
- В других папках читать только документы и код, необходимые для понимания контракта.
- Не удалять и не откатывать чужие изменения. Перед работой проверять git status.
- Не выполнять commit, push, reset, clean или stash самостоятельно.
- Сначала изучать существующее приложение и применимые инструкции; не переписывать приложение без необходимости.
- Каждый последующий этап заканчивать проверкой и отчётом о реально выполненных действиях, изменённых файлах и ограничениях. Не выдавать непроверенное за работающее.

## Секреты, API и тестирование

- Не открывать файлы с секретами для анализа, включая `.env`; не выводить значения переменных окружения.
- Не добавлять ключи в исходники, примеры, логи или ответы.
- Не выполнять реальные запросы к платным API без отдельного явного разрешения пользователя. Наличие ключа не является разрешением.
- Все обычные тесты должны работать без интернета и ключей.
- Не выдавать mock-ответы за результаты настоящих моделей; тестовые подмены должны быть явно обозначены.

## Целевая ответственность сервиса

Это требования к будущей реализации, а не описание уже работающего кода:

1. Принимать подготовленный JSON от Go-backend.
2. Обращаться к OpenAI для анализа аномалий и предложений аналитических корректировок.
3. Проверять предложения модели и применять только допустимые корректировки к отдельной аналитической копии данных. Исходные данные сохранять неизменными.
4. Выполнять прогноз спроса и расчёт закупки Python-кодом.
5. Обращаться к OpenAI API за понятным объяснением рассчитанного результата.
6. Возвращать результат Go-backend.

Единственный внешний AI-провайдер — OpenAI. Анализ и объяснение — разные задачи, используют один ключ и общий lifecycle-клиент AsyncOpenAI. Модель задачи берётся из OPENAI_ANALYSIS_MODEL / OPENAI_EXPLANATION_MODEL, при пустом значении — OPENAI_MODEL. При ошибке доступа не менять модель автоматически. Только официальный endpoint https://api.openai.com/v1, Responses API, Structured Outputs/Pydantic, store=false, без tools. Не обещать, что store=false исключает всё хранение у провайдера.

Модель возвращает предложения, а не dataset. Статус назначает приложение, по умолчанию needs_review; модель не может присвоить accepted. Проверять ссылки на строки, даты, обезличенных клиентов, типы и действия. Невалидный/пустой/обрезанный ответ или отказ — ошибка анализа. Предложения модели сами по себе не разрешают корректировки. В MVP допускаются только подтверждённые бизнес-метки и проверяемые правила; исходные продажи неизменны.

- Не читать Excel в основном AI pipeline: техническая обработка Excel относится к Go-backend.
- Не реализовывать отправку заказов поставщикам.
- Не выдумывать существующие файлы, endpoints, схемы JSON и названия колонок. Отделять найденный контракт от предложений.
- Использовать контракт Go → AI из `alibekAI.md`, найденный после исходного аудита. Расширения этого контракта документировать в `contracts/README.md` и согласовать с владельцем Go до live-интеграции. Публичные маршруты из задания frontend не считать внутренними маршрутами AI-сервиса.

## Текущий этап

Этап 5: существующий lifecycle analysis service подключён к pipeline перед расчётом; explanation service использует тот же OpenAI-клиент после расчёта. На товар максимум один логический анализ и одно объяснение, товары обрабатываются последовательно. Повторы только SDK. В mock нет сети, live без ключа возвращает явную ошибку. Ошибки анализа — deterministic fallback с needs_review; ошибки объяснения — template. Числа и обязательные предупреждения формирует Python. Предложения модели не превращать в бизнес-подтверждение. Контракт/его enum не менять; фактические источники этапов указывать в RESULT_SOURCES. Реальные API-вызовы без явного разрешения не выполнять.


Этап 6: проверка и передача. Новые функции не добавлять; только критические исправления и тесты. Ручной live smoke — исключительно явный --live, ALLOW_EXTERNAL_AI=true, ключ из окружения, один синтетический товар, максимум один анализ/объяснение и ноль повторов SDK. Не запускать его самостоятельно.
