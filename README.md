# SupplyLens

**Планирование закупок и пополнения склада для «Электрокомплект».**

SupplyLens помогает менеджеру закупа перейти от ручных расчётов в Excel к проверяемым рекомендациям: увидеть потребность, разобрать разовые крупные продажи, скорректировать количество и подготовить заказ в CSV. Решение о закупке остаётся за менеджером; приложение не отправляет заказ поставщику.

Проект команды **NovaCoders** для кейса **HackAlem AI «Автоматизация формирования заказов поставщикам»**.

## Возможности

### Рабочее место менеджера

- Шесть источников Excel: выбор файлов, drag-and-drop, размер, статус и сообщения об ошибках.
- Срок поставки, страховой запас и выбор дополнительных складских остатков.
- Таблица закупочных решений с поиском по названию, артикулу и коду 1С; фильтры по категории, срочности, решению и предупреждениям.
- Карточка товара с графиком спроса, расчётом потребности, разбором аномалии и решением менеджера.
- Ручное количество, комментарий и предупреждения о минимальной партии или кратности без скрытого округления введённого значения.
- Предпросмотр состава заказа, подтверждение, выгрузка CSV и повторное скачивание.

| Решение | Значение |
| --- | --- |
| BUY — «Заказать» | Есть потребность в пополнении. |
| NO_BUY — «Не заказывать» | По расчёту запаса достаточно. |
| REVIEW — «Проверить» | Есть неопределённость или проблема данных, требующая решения менеджера. |

Неизвестная стоимость отображается отдельно от нулевой. Коды 1С и артикулы обрабатываются как строки, чтобы сохранять ведущие нули и другие значимые символы.

### Расчётный сервис

Backend проверяет и сопоставляет данные XLSX, выделяет кандидатов на разовые продажи и рассчитывает потребность с учётом сезонности, роста, периодов отсутствия товара, страхового запаса, свободного остатка и поставок в пути. Предлагаемое количество округляется вверх до известной кратности заказа.

Подозрительная операция не исключается автоматически: менеджер подтверждает, следует ли оставить её в регулярном спросе. Формулы, ограничения и примеры описаны в [документации backend](backend/README.md).

## Быстрый запуск

Ниже приведены команды для **PowerShell в терминале VS Code**. Начальная папка — корень этого репозитория. Для frontend нужен Node.js 22.12+ с npm; используемая локально версия — Node.js 24.12.0. Для backend нужен **Go 1.26.1 или новее**, согласно [go.mod](backend/go.mod).

### 1. Открыть интерфейс

cd frontend
npm ci
npm run dev -- --port 5174

Откройте [http://127.0.0.1:5174](http://127.0.0.1:5174). Оставьте терминал с Vite работающим; Ctrl+C останавливает сервер.

Для демонстрации backend и API-ключи не нужны. По умолчанию выбран режим **«Демо»**.

1. Откройте **«Параметры»** — тестовый набор загрузится автоматически.
2. Перейдите в **«Рекомендации»** — появится демонстрационный расчёт.
3. Нажмите на товар, проверьте спрос и при необходимости измените количество.
4. Откройте **«Готовый заказ»**, проверьте состав и нажмите **«Подтвердить и скачать CSV»**.

Можно сразу открыть «Рекомендации» или «Готовый заказ»: недостающий демонстрационный набор будет подготовлен автоматически. Переход между вкладками сохраняет текущий расчёт и ручные решения. CSV формируется по явному подтверждению.

Обычная команда npm run dev использует порт **5173**. В примерах выбран **5174**, как в текущем запуске проекта.

### 2. Запустить Go API отдельно

В новом терминале, из корня репозитория:

cd backend
$env:HTTP_ADDR = "127.0.0.1:8080"
$env:CORS_ORIGINS = "http://127.0.0.1:5174,http://localhost:5174"
go mod download
go run ./cmd/api

В ещё одном терминале проверьте состояние сервера:

Invoke-RestMethod -Uri "http://127.0.0.1:8080/healthz"

Ожидаемый результат — status: ok. Переменные backend читаются из окружения; файл .env автоматически не загружается.

Этот запуск поднимает сервер. Для полного сценария через текущий интерфейс сначала требуется [согласовать API-контракты](#api-и-совместимость).

### 3. Получить тестовые XLSX для backend

В отдельном терминале, из папки backend:

go run ./cmd/demo -out data/demo

Команда создаёт шесть синтетических XLSX в backend/data/demo/. В серверном наборе **4 SKU**; встроенное демо интерфейса содержит **16 товаров**. Это два разных тестовых набора. Полный серверный сценарий import → run → patch → export приведён в [backend/README.md](backend/README.md#demo-flow).

Текущий backend рассчитан на supplier: "SystemElectric". Поддержка файлов другого поставщика требует отдельной проверки схемы импорта.

## Демо и реальные расчёты

| Режим | Поведение |
| --- | --- |
| **Демо** | Фиксированные ответы из frontend/src/api/demoApi.ts. Загрузка Excel имитируется, параметры не пересчитывают прогноз, NVIDIA/OpenAI не вызываются. |
| **Go API** | HTTP-запросы через frontend/src/api/supplyLensApi.ts. Демоданные при ошибке сервера не подставляются. Для текущего backend требуется адаптация контракта. |

Исходный frontend-демонабор: **8 позиций к заказу, 5 без заказа, 3 на проверке**. Подтверждение аномалии и ручные правки изменяют демонстрационный ответ. Экспорт помечен DEMO и **не предназначен для закупки**.

Обновление страницы сбрасывает состояние интерфейса. Перезапуск backend удаляет загруженные наборы, расчёты и подтверждения, поскольку они хранятся в памяти.

### Что нужно согласовать

| Область | Текущее расхождение |
| --- | --- |
| Импорт | Четыре поля multipart имеют разные имена; см. таблицу источников выше. |
| Ответ импорта | Frontend ожидает supplier, usable, productsFound и другие поля. Backend возвращает products, fullyMatchedProducts, diagnostics. |
| Параметры расчёта | Frontend отправляет useNvidiaReview и useOpenAIExplanation. Backend не принимает эти поля и отклоняет неизвестные поля с HTTP 400. |
| Ответ расчёта | Frontend ожидает status, warnings, exportReady, график demand и explanation. Серверная модель отличается; например, baseMonthlyDemand соответствует другому имени поля в интерфейсе — baseDemand. |
| Изменение позиции | Frontend использует managerComment и решения EXCLUDE / REGULAR / REVIEW для отдельной аномалии. Backend принимает comment и EXCLUDE / KEEP для всех кандидатов позиции. |
| Итоги и экспорт | Frontend ожидает сводку заказа по BUY. Backend суммирует предварительные позиции и экспортирует только явно подтверждённое положительное количество, включая подтверждённые позиции REVIEW. Сам вызов экспорта не утверждает позиции. |
| Ошибки | Frontend читает сообщение верхнего уровня message; backend возвращает error.message вместе с кодом и деталями. |

Согласование должно охватывать не только названия полей, но и смысл подтверждения, состав экспортируемого заказа и расчёт итогов. До этого переключатель «Go API» не обеспечивает сквозной рабочий сценарий с сервером из данного репозитория.

## Частые вопросы

**Порт занят.** Остановите предыдущий экземпляр Vite через Ctrl+C или задайте свободный порт: npm run dev -- --port 5175. Для запросов к backend добавьте новый origin в CORS_ORIGINS.

**Вкладки открыты, но расчёта нет.** В «Демо» пример подготавливается автоматически. В Go API сначала нужен успешный импорт и расчёт; незаполненный раздел показывает следующий шаг. Также проверьте совместимость контрактов выше.

**После обновления страницы данные исчезли.** Состояние frontend хранится в памяти вкладки. Backend также хранит данные в памяти своего процесса.

**CSV содержит только заголовок.** В текущем Go API экспортируются только количества, явно подтверждённые через PATCH. Наличие рекомендации BUY само по себе не является подтверждением.

**Go сообщает о неподходящей версии.** Модуль требует Go 1.26.1+. Проверьте go version и доступность нужного toolchain.

**На Windows esbuild сообщает Access is denied для родительских папок.** В проекте есть режим совместимости для ограниченной файловой среды. Из папки frontend:

$env:SUPPLYLENS_RESTRICTED_FS = "1"
npm run dev -- --port 5174

## Ограничения MVP

- API-контракты frontend и backend пока различаются; автоматическое подключение не завершено.
- Расчёт backend привязан к SystemElectric и срезу **22.09.2026**. Последние полные месяцы: сентябрь 2025 — август 2026; неполный сентябрь 2026 исключается из базовой истории.
- Прогноз основан на прозрачных эвристиках. Периоды отсутствия товара оцениваются по месячным данным, а не по ежедневной истории наличия.
- Внешний AI не подключён. Интерфейсные AI-объяснения в демо являются синтетическими.
- Долговременное хранение, авторизация, роли и отправка заказов поставщикам не реализованы.
- Основной интерфейс рассчитан на desktop. На узком экране таблица прокручивается внутри своего контейнера, карточка товара занимает всю ширину.
