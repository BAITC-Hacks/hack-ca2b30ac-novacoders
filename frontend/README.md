# SupplyLens

Frontend MVP для менеджера закупа «Электрокомплект». React + Vite + TypeScript + Tailwind CSS, иконки Lucide и графики Recharts. Один экран с четырьмя состояниями: `IMPORT → CONFIGURE → RESULTS → APPROVED`.

Frontend размещён в папке frontend общего проекта. Запускайте команды ниже из этой папки. Исходные Excel и коммерческие данные в приложение не включены.

## Запуск

Нужен Node.js 22.12+ или 24 LTS и npm.

```bash
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Для VS Code есть `supplylens.code-workspace` и задачи запуска, сборки и тестов. Можно также открыть папку, содержащую этот README и `package.json`.

В ограниченной Windows-среде, если esbuild пишет `Access is denied` при просмотре родительских папок:

```powershell
$env:SUPPLYLENS_RESTRICTED_FS='1'
npm run dev
```

Этот совместимый режим разрешает точные пути зависимостей через Node, не добавляя доступ к файловой системе. Обычному запуску он не требуется. `configLoader runner` используется, чтобы не собирать конфигурацию отдельным проходом esbuild.

## Демонстрация

По умолчанию включён **Демо**, явно обозначенный в шапке и на рабочих экранах. Нажмите **Использовать демо-данные**, затем **Рассчитать заказ**.

Набор содержит 16 синтетических товаров SystemElectric: 8 к заказу, 5 без заказа, 3 на проверку. Эти показатели — тестовые ответы, а не результат обработки приложенных пользователем Excel.

В демо доступны:

- Имитация загрузки шести Excel с показом имени, размера и статуса; выбор файла и drag-and-drop.
- Результат проверки, настройки срока поставки, страхового запаса и источников остатков.
- Поиск, фильтры решения, категории, срочности и предупреждений.
- Сортировка: REVIEW, критичные BUY, остальные BUY, NO_BUY.
- Правая панель с breakdown, Demand X-Ray, stockout, аномалией и неполным сентябрём.
- Решение по аномалии с обновлением позиции, графика, пояснения и KPI через mock transport.
- Ручное количество и комментарий, проверка целого неотрицательного значения, предупреждение о MOQ/кратности без автоматического округления.
- Экспорт готовых BUY-позиций, успешный экран, повторное скачивание.

Изменение параметров расчёта в демо **не пересчитывает прогноз**. NVIDIA/OpenAI не вызываются. Все сценарии находятся в `src/api/demoApi.ts`; в обычных компонентах нет прогнозной логики. CSV имеет имя с префиксом `DEMO` и маркировку в каждой строке. Он не предназначен для закупки.

## Подключение Go API

1. Скопируйте `.env.example` в `.env.local`.
2. Для локального Go-сервера задайте `API_PROXY_TARGET` (по умолчанию `http://127.0.0.1:8080`). Vite перенаправляет `/api` на этот адрес.
3. Для другого origin задайте `VITE_API_BASE_URL` без завершающего `/api/v1`: например, `https://example.internal`. На сервере требуется соответствующий CORS.
4. Перезапустите Vite и выберите **Go API** в шапке. При смене режима приложение предупреждает о сбросе локальной сессии.

Все `VITE_*` переменные доступны браузеру. Секреты NVIDIA/OpenAI должны храниться только на Go-сервере.

### Контракт, принятый frontend

Реального Go API и OpenAPI-спецификации в материалах нет. Ниже зафиксированы интеграционные ожидания; их потребуется согласовать с разработчиком backend. Типы находятся в `src/types/api.ts`, все HTTP-вызовы — в `src/api/supplyLensApi.ts`.

| Запрос | Тело | Ожидаемый ответ |
|---|---|---|
| `POST /api/v1/import` | `multipart/form-data`: `moq`, `salesDetails`, `monthlyStock`, `monthlySales`, `seasonality`, `inTransit` | `Dataset` |
| `POST /api/v1/runs` | `RunParams` из ТЗ | Завершённый `RunResult` |
| `PATCH /api/v1/runs/{runId}/items/{code1C}` | `ItemPatch` | Полный обновлённый `RunResult`: items, summary, warnings, exportReady |
| `POST /api/v1/runs/{runId}/approve-export` | `{}` | CSV с `Content-Type: text/csv`, опциональным `Content-Disposition` |

Пример результата импорта:

```json
{
  "datasetId": "dataset-001",
  "supplier": "SystemElectric",
  "warehouse": "Алматы",
  "asOf": "2026-09-22",
  "productsFound": 497,
  "matchedProducts": 467,
  "reviewProducts": 30,
  "usable": true,
  "warnings": [],
  "capabilities": {
    "demoDataset": false,
    "nvidiaReview": true,
    "openaiExplanation": true
  }
}
```

`RunResult` содержит `runId`, `supplier`, `asOf`, `status: "COMPLETED"`, `items`, `summary`, `warnings`, `exportReady` и необязательный `exportBlockReason`. Каждая позиция должна содержать поля из `RecommendationItem`, в том числе массивы `warnings`, `anomalies` и `demand` (пустые массивы допустимы). Неизвестная стоимость, MOQ и кратность передаются как `null`, а не как 0.

Изменение количества:

```json
{ "approvedQuantity": 95, "managerComment": "Партия согласована" }
```

Решение по аномалии:

```json
{ "anomalyId": "anomaly-001", "anomalyDecision": "EXCLUDE" }
```

Допустимые решения по аномалии: `EXCLUDE`, `REGULAR`, `REVIEW`. Кнопки доступны только если сервер передал `reviewable: true`. Сервер определяет новое закупочное решение, количество, стоимость, breakdown, график и итоговые показатели. Frontend отображает ответ и не пересчитывает их.

### Возможности и прогресс

Кнопка серверного демо-набора скрыта, пока не задан `VITE_DEMO_DATASET_ENDPOINT`. Этот endpoint вызывается методом POST. Переключатели NVIDIA/OpenAI в реальном режиме скрыты по умолчанию; включайте соответствующие переменные `.env` или возвращайте `capabilities` в ответе импорта, только если Go API поддерживает эти возможности.

Для импорта отображается фактический прогресс передачи байтов через XMLHttpRequest. После 100% передачи frontend отдельно ожидает проверку сервером. Для расчёта показывается индикатор ожидания и перечень этапов без выдуманного процента или утверждения о текущем этапе. Контракт пока предполагает синхронный ответ: фоновые job, polling, SSE и отдельный endpoint прогресса не выдуманы и не реализованы.

Ошибки API могут возвращать `{ "message": "Понятное сообщение" }`. Сетевые ошибки и таймауты обработаны. Предыдущий успешный расчёт остаётся доступен, если повторный запрос не удался. Повторная отправка блокируется на время запроса.

### Подтверждение и CSV

Сервер должен атомарно проверить актуальность run и готовность позиций. REVIEW и NO_BUY не должны входить в закупочный экспорт. Frontend использует серверные `summary` и `exportReady`; локальные фильтры меняют только таблицу, а не состав заказа. Экспортируются все готовые позиции расчёта. Произвольный выбор подмножества позиций не добавлен, поскольку такого тела запроса в ТЗ нет.

Повторное скачивание после успеха использует уже полученный файл и не вызывает approve-export повторно. После изменения позиции старый экспорт перестаёт считаться актуальным. Серверу рекомендуется сделать approve-export идемпотентным по `runId`, чтобы безопасно обрабатывать потерю ответа и повторный запрос.

Поставщику ничего не отправляется. Совместимость CSV с конкретной конфигурацией 1С должен обеспечить backend согласно согласованному шаблону. Для cross-origin скачивания серверу нужен `Access-Control-Expose-Headers: Content-Disposition`, если frontend должен использовать серверное имя файла.

## Проверки и сборка

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run preview
```

Собранное приложение находится в `dist/`. Production-хостинг должен направлять `/api/v1/*` на Go API или использовать `VITE_API_BASE_URL`, заданный на этапе сборки. Vite dev proxy не входит в production bundle.

Тесты проверяют валидацию ручных количеств, MOQ, сортировку, отличие неизвестной и нулевой стоимости, обновление mock-ответа после аномалии, исключение REVIEW из CSV, контракт данных, передачу параметров реальному адаптеру и ошибки экспорта. В браузере проверяется основной демонстрационный путь и узкий экран.

### Переходы между разделами

Все четыре раздела доступны с начала работы. В деморежиме прямой переход в «Параметры» загружает тестовый набор, а переход в «Рекомендации» или «Готовый заказ» при необходимости подготавливает демонстрационный расчёт. Существующий расчёт и ручные решения при переключении сохраняются. Неверные параметры нельзя обойти через навигацию.

«Готовый заказ» сначала показывает состав и итоги для подтверждения. CSV создаётся только по кнопке «Подтвердить и скачать CSV»; сам переход в раздел не утверждает заказ. В Go API переходы не подставляют демонстрационные данные: если данных или расчёта ещё нет, раздел показывает нужный следующий шаг. Во время запроса повторные действия временно блокируются.

## Границы MVP

### Обновлённый интерфейс

Одна горизонтальная навигация объединяет импорт, параметры, рекомендации и готовый заказ. Импорт представлен списком из шести источников. На экране рекомендаций — компактная сводка и таблица с выровненными числовыми колонками. Код 1С и артикул находятся под названием товара; все исходные поля сохранены. Ручное количество показано первым, рядом остаётся исходная рекомендация. Неизвестная стоимость обозначена «Нет цены».

Карточка товара разделена на обзор спроса, расчёт и решение менеджера. Переключение разделов сохраняет введённые значения. На узком экране карточка занимает всю ширину, а горизонтальная прокрутка ограничена контейнером таблицы. API-адаптер, контракты и демонстрационные расчёты при обновлении дизайна не менялись.

### Ограничения

- Реальная обработка Excel, прогнозирование, оценка stockout, AI и формирование боевого CSV требуют Go API. Они не реализованы в браузере и не подтверждены интеграционным запуском с реальным сервером.
- Только demo transport формирует синтетический CSV и имитирует изменение итогов.
- Локальная сессия хранится в памяти; обновление страницы начинает её заново. Долговременное хранение и восстановление расчётов требуют серверного контракта.
- Авторизация, роли, административные страницы и отправка заказа поставщику не добавлены.
- Основной макет ориентирован на 1440×900; на мобильном таблица прокручивается горизонтально, панель товара занимает ширину экрана.
